# Регистрация по ссылке приглашения: 20261007-invite-link-2

Пакет содержит исходники. Установщик собирает новый образ Kan на сервере, пока прежний веб-контейнер работает. Установка выполняется из root-консоли на сервере Kan; пользователь `trs_redmine` используется только для загрузки.

```bash
bash /home/trs_redmine/kanban-release-20261007-invite-link-2/deploy/invite-upgrade-root.sh
```

Допускается только плоская установка `/opt/kanban/compose.yml` с текущим образом `trisoft-kan:20261006-task-control-4-polling`. При другой версии или расхождении сохраненного и фактического окружения скрипт остановится до переключения.

Изменяется только образ сервиса `web`. `.env`, база, тома, образ `migrate`, Nginx и whitelist остаются прежними. Публичная регистрация и почта остаются отключенными. Новый аккаунт можно создать через действующую локальную ссылку `/invite/CODE`; просроченная или отключенная ссылка не разрешает регистрацию. Существующий механизм принятия приглашения добавляет пользователя в рабочее пространство.

Скрипт проверяет контрольные суммы пакета, ресурсы, прежний образ и настройки, собирает и проверяет образ, создает dump БД и сохраняет предыдущий Compose. После переключения проверяет health, HTTPS/login, отказ API без авторизации, сохранность окружения и остальных существовавших контейнеров. Запросов создания пользователей на рабочей базе не выполняет.

Резервная копия и журналы:

```text
/opt/kanban/backups/upgrade-20261007-invite-link-2/
```

При ошибке после переключения автоматически возвращается прежний Compose и образ web. База не восстанавливается из старого dump: миграций нет, а текущие пользовательские записи должны сохраняться. При сбое до переключения рабочий Kan не меняется. Повтор после успешной установки ничего не пересобирает. После неуспешной попытки нужно сначала разобрать сохраненные журналы; скрипт не перезаписывает резервную копию.

## Исправление заблокированного релиза invite-link-1

Первая попытка собрала образ, но аудит остановил установку из-за High в `@modelcontextprotocol/sdk` 1.29.0 (GHSA-6qxp-vccf-f47h). В web и mcp версия закреплена на исправленной 1.31.0, lockfile обновлен. Порог аудита High/Critical не снижен. Новый label и backup-каталог позволяют установить исправленный пакет без удаления первой попытки, старого образа или журналов.

Установщик новой версии по-прежнему допускает только действующий `trisoft-kan:20261006-task-control-4-polling`: не устанавливать поверх неизвестной версии. Если аудит снова завершится ошибкой, установщик напечатает путь к `image-audit.log` до переключения web. Доступность npm registry и актуальные advisory проверяются заново на сервере при установке.

Для ручного отката успешного обновления: убедиться, что после установки `.env` и Compose не редактировались, сохранить текущую конфигурацию, вернуть `previous-compose.yml` из указанной резервной копии в `/opt/kanban/compose.yml` и выполнить `docker compose --project-name trisoft-kan --env-file /opt/kanban/.env -f /opt/kanban/compose.yml up -d --no-deps --no-build --pull never web`. Старый образ сохраняется. Не восстанавливать dump поверх текущих записей.

Локальная проверка исходного invite-link-1: 45 тестов авторизации, включая реальный HTTP-запрос Better Auth с адаптером в памяти; запрос репозитория проверен на отдельной PostgreSQL-совместимой базе PGlite в памяти; 6 тестов сохранения конфигурации; ShellCheck и репетиция установщика с имитацией успешного запуска, повторной установки, сбоя сборки, отказа health и расхождения env. Проверки не подтверждают установку или регистрацию на рабочем сервере.

## Проверка исправленного invite-link-2: 07.10.2026

- Реальный production-образ `linux/amd64` собран из пакета; внутри только MCP SDK 1.31.0. Неизмененный image audit: 284 пакета, High=0, Critical=0, Moderate=8, Low=2. Устранен блокирующий High, не все предупреждения безопасности.
- Vitest: MCP 13, auth 45, web 46, API 192 — всего 296 тестов. Typecheck web/mcp/auth и build-зависимостей: 11 задач успешно.
- Проверки layout/защиты installer: 8; регрессия аудита: 6 (High/Critical и ошибка реестра блокируют образ). Bash syntax, Prettier и `git diff --check` прошли.
- HTTP task control: 23 сценария, Redmine только mock. Новый production-образ отдельно запущен локально: health/login=200, GET MCP=405, POST MCP без ключа=401, integration API без токена=401. Тестовый контейнер и локальный сборщик остановлены.

Это локальные доказательства готовности пакета, не подтверждение установки invite-link-2 на production. На сервере установщик повторит сборку, актуальный аудит и проверки перед переключением.
