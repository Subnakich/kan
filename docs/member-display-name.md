# Изменение имени участника администратором

Интерфейс: **Участники → ⋯ у участника → Изменить имя участника → Сохранить**. Пункт доступен администратору с `member:edit` для другого активного участника, у которого уже есть аккаунт. Для своего профиля — штатные настройки аккаунта. Приглашенных без аккаунта, приостановленных и удаленных участников эта функция не меняет.

Изменяется глобальный `user.name`, а не отдельный ник пространства. Форма предупреждает, что имя обновится во всех пространствах. Email, пользовательский и членский ID, роли, назначения карточек и привязки Telegram/Redmine сохраняются. API справочника участников бота получает новое имя при следующем чтении; ранее скачанный JSON/промпт или собственный кеш бота автоматически не переписываются.

## Контракт и безопасность

- tRPC: `member.updateDisplayName({workspacePublicId, memberPublicId, name})` → `{success:true,name}`.
- Штатный авторизованный REST: `PUT /api/v1/workspaces/{workspacePublicId}/members/{memberPublicId}/name`, тело `{name}`. Это не endpoint `/api/integrations/v1` для сервисного токена бота.
- Требуются действующая авторизация, активное членство администратора именно этого пространства и разрешение `member:edit`. Одного пользовательского override `member:edit` без роли admin недостаточно.
- Public ID ровно 12 символов; имя обрезается по краям, 3–255 символов, без `@` и управляющих символов. Граница согласована с существующим `varchar(255)`.
- Отвергаются чужой member ID, удаленное пространство и участник без активного аккаунта. SQL UPDATE повторно проверяет актуальное членство администратора и цели, статус и отсутствие soft delete.
- Обновляются только `user.name` и `updatedAt`. В ответе нет внутреннего user ID. В журнале административного действия фиксируются actor и public ID пространства/участника.
- Миграции, зависимости, env и изменения бота не требуются. После успеха UI инвалидирует кеш запросов, чтобы обновились участники, карточки и другие пространства.

## Карта для синхронизации форка

- `apps/web/src/views/members/index.tsx` — пункт меню и штатный Modal.
- `apps/web/src/views/members/components/EditMemberNameModal.tsx` — штатные Input/Button, подтверждение и ошибки.
- `packages/api/src/routers/member.ts` — авторизация/проверка границ, роут уже подключен в root.
- `packages/db/src/repository/member.repo.ts` — атомарный защищенный UPDATE аккаунта.
- `packages/shared/src/member-display-name.ts` и экспорт `src/index.ts` — единая проверка для UI/API.
- Каталоги `apps/web/src/locales/*/messages.json` и скомпилированные `messages.ts` — новые строки, существующие переводы сохранены.

Проверки: unit в `member-name.test.ts`/`member-display-name.test.ts`, SQL в изолированной PGlite — `member-name.repo.integration.test.ts`. Реальный локальный HTTP/PostgreSQL smoke: `KAN_DEMO_URL=http://localhost:3000 node tools/task-control/member-name-test.mjs` внутри web-контейнера. Скрипт создает только новые явно названные локальные fixtures и блокирует production URL; проверяет имя в API бота, неизменность email/ID/карточки и отказ неадминистратору/чужому пространству. Рабочие аккаунты не переименовывать в автоматическом тесте.
