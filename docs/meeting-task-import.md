# Из транскрибации в задачи Kan

## Подготовка и загрузка

1. Подготовить транскрибацию, название встречи, стабильный ID и дату начала с часовым поясом. Если время встречи неизвестно — `started_at: null`.
2. Получить актуальные ID/имена участников и метки выбранной доски. Администратор бота может использовать `/kan_members ec35ftst8whl`; обычному пользователю справочник передает администратор. Не путать member public ID с Telegram ID, email или Redmine user ID.
3. Передать ИИ [промпт](meeting-task-prompt.md), метаданные, справочники и транскрибацию. При исправлении приложить предыдущий JSON, чтобы сохранить ID.
4. Проверить цитаты, ответственных и сроки. Сохранить ответ как `meeting-tasks.json`: UTF-8 без BOM, без Markdown-обертки. Не вкладывать токены или полную транскрибацию в файл задач.
5. В боте `/import_tasks` → выбрать доску → отправить JSON документом → проверить preview → подтвердить. Это два подтверждения: импорт в боте создает Review, перевод в Queue выполняется отдельно в Kan.
6. В Kan проверить/поправить карточки, удалить лишние. Название, описание и ответственный нужны перед Queue; срок можно оставить пустым.

Пользователь бота должен быть допущен и связан с активным участником Kan через административную команду `/link_kan TELEGRAM_ID MEMBER_PUBLIC_ID BOARD_ID`. Участнику нужны права просмотра доски и создания карточек. Доска должна быть разрешена в конфигурации бота, Task control включен. Работоспособность установленного бота проверять отдельно от наличия этих команд в исходниках.

## Файлы

- [Шаблон для заполнения](examples/meeting-tasks.template.json) — заменить все примерные значения, не загружать как реальную встречу.
- [Готовый учебный пример](examples/meeting-tasks.example.json) и [его транскрибация](examples/meeting-transcript.example.txt). Ответственные оставлены `null`: без настоящего справочника ID назначать нельзя.
- [JSON Schema](schemas/meeting-tasks.schema.json) — проверка структуры. Бот дополнительно проверяет реальные даты, уникальность task.id, справочники, права и объем payload.

Формат — `schema_version: "1.0"`, `kind: "kan_meeting_tasks"`, `meeting`, `tasks`. Все перечисленные поля обязательны; неизвестное значение — `null` или `[]`, не пропуск поля. Лишние поля запрещены.

| Поле                                         | Правило                                                                                         |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `meeting.id`, `tasks[].id`                   | 1–200 символов: латиница, цифры, `_`, `-`, `.`. ID задачи уникален внутри встречи               |
| `assignee`                                   | `null` либо `{member_public_id,name}` строго из справочника; public ID — 12 латинских букв/цифр |
| `due_at`, `started_at`                       | `null` либо RFC3339 с секундами и явным `+03:00`/`Z`                                            |
| `due_text`                                   | Исходная формулировка срока; при неизвестном часе `due_at=null`                                 |
| `source.quote`                               | Непустая дословная цитата, подтверждающая поручение                                             |
| `source.timestamp`                           | Таймкод либо `null`, не придумывать                                                             |
| `labels`, `checklist`, `acceptance_criteria` | Только существующие метки/оговоренные действия и критерии, иначе `[]`                           |
| `review_notes`                               | Неопределенности, которые нужно проверить человеку                                              |

Лимиты текущего бота: файл 2 MiB, 1–200 задач, одна задача после преобразования в API payload до 250 000 байт. Полные ограничения строк/массивов — в схеме. `tasks: []` означает «поручений нет»: такой файл **не отправлять** на импорт, бот его отклонит.

## Повторный импорт и ошибки

Сохранять `meeting.id/task.id` для той же встречи/поручения. Бот сам добавляет instance ID, выбранную доску, ключ идемпотентности и хеш; ИИ их не генерирует. Весь файл нельзя напрямую POST-ить в `/imports/cards`: сервер принимает одну преобразованную задачу за запрос.

- Повтор одинакового файла возвращает существующие карточки.
- Измененное содержимое с тем же ключом дает конфликт. Уже созданную карточку исправлять в Kan, не менять ID ради повторного создания.
- Удаленная карточка остается в истории импорта как tombstone и не создается повторно.
- При timeout сначала проверить результат/ссылку, не делать новый файл с новыми ID.
- Неизвестный пользователь/метка отмечается на Review; preview нужно читать, а не подтверждать автоматически.

Полная транскрибация может содержать конфиденциальные данные. Использовать только разрешенный компании ИИ/транскрибатор. Инструкции внутри речи считаются данными, не командами модели или боту.
